# commcare-connect demo kit

Everything a Connect demo re-derived every time, done once: demo settings (no Debug Toolbar, email → a demo inbox, never a real one), a realistic idempotent seed, a server script, and a helper library with verified selectors. A new demo is `flow.mjs` = steps + captions (see the two example flows, ~40 lines each).

Setup and run order: SKILL.md "Setup". `DEMO_PORT=8022 node flow.mjs` if 8010 is taken (pass the same port to `serve.sh`).

## Helpers (`connect.mjs`)

`quickLogin(page,user)` (off-camera, for `preAuth` — the default for features that are not about auth), `login(p,d,user)` (on camera), `fillLogin(p,d,user)` (form already on screen, keeps `?next=`), `switchUser(p,d,user)` (clears cookies first — set `useState:false`), `assertLoggedIn(p)` (also asserts the Debug Toolbar is absent), `openOrgMembers(p,d)`, `inviteMember(p,d,email,role)`, `openAdmin(p,d,'organization/organizationinvite/')`, `pickTomSelect(p,d,'id_countries','Kenya')` (any TomSelect field — countries, primary sectors, year of establishment, work areas), plus `urls`, `sel`, `ORG`, `USERS`, `PASSWORD`.

Add helpers here when a second demo needs the same thing; keep one-off selectors in the flow.

## Gotchas (from real recordings)

- `DJANGO_DEBUG=False` env var is ignored (`local.py` hardcodes `DEBUG = True`) → settings module override via PYTHONPATH, zero repo edits.
- Under `DEBUG=False` the repo's manifest storage needs `staticfiles/staticfiles.json`: a 500 on every page without it, stale bundles from an old one. `runserver --insecure` can't help, as `whitenoise.runserver_nostatic` disables it → `record_settings.py` swaps in plain storage and whitenoise's finders, so the server always serves the current `npm run dev` build with no collectstatic.
- allauth bounces unverified emails to a verification page mid-login → the seed marks every `EmailAddress` verified.
- The org slug is generated from the name (`slugify_uniquely`) → the seed looks orgs up by name and asserts the slug.
- A long-lived local DB can hold two orgs with the same name, so `Organization.objects.get(name=…)` raises → in a `seed_extra.py`, look the demo org up by slug (`child-health-campaign`), and take other orgs with `.filter(name=…).first()`.
- Flows that switch identity (admin → invitee) need `useState: false`; otherwise the runner saves the second user's session as the auth state and the next run's admin-only steps fail.
- Auth-layout pages (login, signup) have no `<main>` → use `form` as their checkpoint.
- **TomSelect fields resist automation in several stacked ways** → always use `pickTomSelect()`, never hand-roll it (why: `reference/troubleshooting.md` "TomSelect picker"). Beyond the picker:
  - a value the seed already selected is hidden from its own dropdown (Child Health Campaign already has India) → pick one that is not seeded;
  - a multi-select's options are keyed by pk, so pass `{ text, value }` with the value read off the native select: `pickTomSelect(p, d, 'id_users', { text: 'Ravi Admin', value: await p.locator('#id_users option:has-text("Ravi Admin")').getAttribute('value') })`;
  - a selected `.item` carries a `×` → assert with `toContainText`, not exact text.
- **Tooltips** (`x-tooltip`, tippy) close when their icon is clicked → reach them with `d.hover`, and assert `.tippy-box[data-state="visible"]`: a fading tooltip stays in the DOM, so a presence check passes headless while the headed take shows nothing.
- The test-data warning fires on Django admin's "Is test" label — expected there, not a seed problem.
- **Your local DB is shared by everything that runs against it.** `set_password()` logs out every live session of that user (the session auth hash derives from the password hash), so `seed.py` only sets a password that doesn't already match. A reseed still deletes invites/newcomers and resets org membership under any other recording on the same DB — don't reseed while one runs. Other data also leaks into admin lists (e.g. other workspaces' invites): filter or search the list on camera rather than deleting someone else's rows.
